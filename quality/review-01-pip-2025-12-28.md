## Points d'attention

### PipWindow.qml

| Severite | Point | Detail |
|----------|-------|--------|
| nit: | Couleurs en dur | Plusieurs couleurs hardcodees (`#000000`, `#FFFFFF`, `#40FFFFFF`) au lieu d'utiliser BlueTheme. Recommande pour coherence future. |
| nit: | Radius 16 vs 12 | Le plan specifie 12px de coins arrondis (ligne 59 du plan), le code utilise 16px (ligne 105). Difference mineure mais notable. |
| suggestion: | Canvas repaint | Le Canvas du resize handle pourrait beneficier d'un trigger de repaint sur changement de taille. |

```qml
// Ligne 105 - Actuel
radius: 16

// Plan specifie
radius: 12
```

### PipPlaceholder.qml

| Severite | Point | Detail |
|----------|-------|--------|
| nit: | Caractere Unicode | L'icone fleche `\u2199` (ligne 137) pourrait ne pas etre disponible sur toutes les polices. Canvas serait plus robuste. |

### PlayerControlBar.qml

| Severite | Point | Detail |
|----------|-------|--------|
| question: | Canvas repaint | Le Canvas de l'icone PiP ne se repeint pas quand `pipActive` change. L'etat actif est-il visible visuellement sur le bouton ? |

**Verification** : Le bouton utilise `ControlButton` avec `active: controlBar.pipActive` - c'est le composant parent qui gere l'apparence active, pas le Canvas. OK.

### main.qml

| Severite | Point | Detail |
|----------|-------|--------|
| nit: | Null safety | Les callbacks dans `Connections` (ligne 244-255) pourraient verifier `playerLoader.item` avant d'acceder aux proprietes. |

```qml
// Actuel (ligne 244-248)
function onPlayingChanged() {
  if (pipWindow.visible && playerLoader.item) {
    pipWindow.playing = playerLoader.item.playing
  }
}
// C'est correct, le check est present
```

**Verification** : Le code fait deja le check `playerLoader.item !== null`. OK.
